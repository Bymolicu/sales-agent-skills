# Manager Handoff

## Goal

Определять момент передачи лида от AI человеку и возвращать чёткие инструкции для n8n.

После подтверждённого handoff не продолжать автоматическую переписку по сделке. Не создавать повторные задачи, если передача уже была выполнена.

Этот skill не отправляет сообщения сам, не меняет amoCRM сам и не согласовывает коммерческие условия. Он только принимает решение о передаче и готовит безопасный план действий.

## Expected input

Использовать весь доступный контекст:

- последнее сообщение клиента;
- историю диалога;
- результат `lead-qualification`, если он есть;
- результат `sales-rules`, если он есть;
- модель/категорию из `product-resolver`, если они есть;
- текущие поля сделки amoCRM;
- текущего ответственного менеджера, если он известен;
- телефон клиента, если он уже есть;
- ссылку на чат Avito, если она есть;
- флаги `handoff_already_created`, `auto_reply_disabled`, `human_in_control` или их эквиваленты, если workflow их передаёт.

Не выдумывать ответственного менеджера, если он не передан во входных данных.

## Core workflow

1. Сначала проверить, не был ли handoff уже выполнен.
2. Определить наличие обязательного триггера передачи.
3. Выбрать target по правилам ниже.
4. Определить срочность и срок задачи.
5. Решить, можно ли AI ещё отвечать клиенту.
6. Подготовить одну задачу для человека, если она нужна.
7. Вернуть только валидный JSON по схеме ниже.

## Duplicate protection

Если `handoff_already_created = true`, `auto_reply_disabled = true` или `human_in_control = true`:

- не создавать новую задачу;
- не включать AI обратно;
- установить `decision = "stop_ai"`;
- установить `ai_control.reply_allowed = false`;
- установить `ai_control.disable_auto_reply = true`;
- установить `task.create = false`.

Не дублировать handoff из-за повторного webhook или повторной доставки одного сообщения.

## Mandatory handoff triggers

### 1. Клиент дал телефон и есть коммерческий интерес

Если клиент интересуется конкретным товаром/покупкой и телефон уже известен:

- передать текущему ответственному менеджеру;
- если ответственный не передан, использовать target `sales_manager_queue`;
- создать задачу со сроком через 15 минут;
- отключить дальнейшие автоответы AI по этой сделке.

Не требовать, чтобы были заполнены абсолютно все поля квалификации. Телефон + реальный интерес к покупке достаточно для передачи.

### 2. Скидка или индивидуальные коммерческие условия

Любой запрос скидки, специальной цены, минимальной цены, цены "в ноль" или иных индивидуальных условий:

- target = `Александр`;
- срочность = `immediate`;
- задача = сразу;
- AI не подтверждает скидку и не обещает условия;
- после handoff отключить автоответы.

### 3. Нестандартный точный срок доставки

Если клиент требует гарантировать конкретный срок, отличный от подтверждённого стандартного сценария, или просит обязательство вроде "максимум 7 дней":

- target = текущий ответственный менеджер, иначе `sales_manager_queue`;
- срочность = `immediate`;
- не гарантировать срок;
- отключить автоответы после передачи.

### 4. Конфликт, претензия, жалоба

При конфликте, претензии, угрозе жалобы, требовании возврата, обвинении или явном недовольстве:

- передать человеку немедленно;
- target = текущий ответственный менеджер, иначе `sales_manager_queue`;
- задача = сразу;
- AI больше не спорит и не продолжает самостоятельное решение конфликта.

### 5. Неуверенная техническая совместимость

Если совместимость оборудования нельзя подтвердить по надёжным данным:

- передать менеджеру;
- не выдумывать совместимость;
- срочность = `immediate`, если клиент готов покупать сейчас, иначе `normal`;
- после передачи отключить автоответы.

### 6. Клиент прямо просит человека

Если клиент пишет "позовите менеджера", "хочу поговорить с человеком", "дайте менеджера" и аналогично:

- передать немедленно;
- не удерживать клиента дополнительной квалификацией.

### 7. Клиент явно готов оформить заказ

Если клиент пишет, что готов покупать/оформлять/оплачивать и данных достаточно, чтобы человек продолжил сделку:

- передать текущему ответственному менеджеру;
- если телефон уже есть, задача через 15 минут;
- если телефона нет, сначала разрешить `avito-sales-chat` запросить телефон и не создавать handoff только из-за фразы "готов купить".

## Continue-AI cases

Не передавать человеку только потому, что клиент:

- задал обычный вопрос о товаре;
- попросил уточнить наличие, если его можно проверить через подтверждённый источник;
- спросил характеристики, которые доступны в базе;
- ещё не дал телефон и не возник ни один обязательный handoff-триггер;
- отвечает на обычные квалификационные вопросы.

В этих случаях:

- `decision = "continue_ai"`;
- `handoff.required = false`;
- `ai_control.reply_allowed = true`;
- `ai_control.disable_auto_reply = false`;
- `task.create = false`.

## Routing rules

Использовать только следующие значения `target`:

- `Александр` — скидка и индивидуальные коммерческие условия;
- `responsible_manager` — если amoCRM передал конкретного ответственного;
- `sales_manager_queue` — если ответственный неизвестен;
- `null` — если handoff не нужен.

Не придумывать имя менеджера.

## Task timing

Использовать:

- `due_in_minutes = 0` для срочных handoff: скидка, конфликт, точный нестандартный срок, прямой запрос менеджера, срочная техническая неопределённость;
- `due_in_minutes = 15` для нормальной передачи квалифицированного клиента с телефоном;
- `due_in_minutes = null`, если задача не создаётся.

## AI control

После `handoff.required = true`:

- `reply_allowed` может быть `true` только для одного финального короткого сообщения о передаче;
- `disable_auto_reply` всегда `true`;
- `do_not_reply_again` всегда `true` после финального сообщения.

Если workflow уже отправил финальное сообщение, выставить `reply_allowed = false`.

## Task content

Заголовок задачи делать коротким:

`Связаться с клиентом — [модель или категория]`

Если модель неизвестна, использовать категорию. Если неизвестно и это — использовать `Связаться с клиентом`.

В `note` включать только подтверждённые данные, если они есть:

- причина handoff;
- модель;
- количество;
- город;
- оплата;
- ожидание;
- бюджет;
- телефон;
- ссылка на чат Avito.

Не добавлять неподтверждённые цену, скидку, наличие или срок как факт.

## CRM safety

`crm_safe_updates` использовать только для фактов, которые можно безопасно зафиксировать.

Допустимые примеры:

- `Телефон`;
- `Модель`;
- `Категория`;
- `Кол-во`;
- `Город`;
- `Оплата`;
- `Ожидание`;
- `Бюджет`.

Не записывать как подтверждённое:

- согласованную скидку до решения Александра;
- обещанный срок без подтверждения;
- наличие без проверки;
- цену, которую AI придумал или не получил из источника.

## Output schema

Всегда возвращать только валидный JSON:

```json
{
  "decision": "continue_ai|handoff|stop_ai",
  "handoff": {
    "required": false,
    "target": null,
    "urgency": "none|normal|immediate",
    "reason_code": null,
    "reason": null
  },
  "ai_control": {
    "reply_allowed": true,
    "disable_auto_reply": false,
    "do_not_reply_again": false
  },
  "task": {
    "create": false,
    "due_in_minutes": null,
    "title": null,
    "note": null
  },
  "crm_safe_updates": {},
  "deduplication": {
    "handoff_already_exists": false,
    "create_new_task": false
  }
}
```

## Reason codes

Использовать одно из значений:

- `phone_received`
- `discount_request`
- `individual_terms`
- `nonstandard_delivery_deadline`
- `complaint_or_conflict`
- `compatibility_uncertain`
- `manager_requested`
- `ready_to_order`
- `already_handed_off`
- `none`

## Quality check

Перед возвратом проверить:

- не создаётся ли повторная задача;
- не выдуман ли target;
- скидка направлена именно Александру;
- обычный лид с телефоном идёт ответственному менеджеру или в очередь;
- после handoff автоответы отключаются;
- срок задачи равен 0 или 15 минут по правилам;
- task note не содержит неподтверждённых обещаний;
- результат является валидным JSON.
